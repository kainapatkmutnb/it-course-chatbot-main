# Non-Student Role Isolation & Deterministic Identity Routing

Status: accepted

## บริบท (Context)

ในระบบแชทบอทให้คำปรึกษาหลักสูตร (`IT Assistant`) บัญชีผู้ใช้งานระบบแบ่งออกเป็น 4 บทบาทหลักตามสิทธิ์การเข้าถึง ได้แก่:
1. **นักศึกษา (`student`)**: ผู้ใช้งานหลักที่มีแผนการเรียน (`StudyPlan`), หลักสูตรที่กำลังศึกษา (`enrolledCurriculum`), ชั้นปี/ภาคการศึกษาจริง (`currentStudentAcademicTerm`) และประวัติผลการเรียน
2. **ผู้ดูแลระบบ (`admin`)**, **อาจารย์ผู้สอน (`instructor`)**, และ **เจ้าหน้าที่ (`staff`)**: บัญชีบุคลากรที่เข้ามาบริหารจัดการระบบ ติดตามนักศึกษา หรือจัดการหลักสูตร ซึ่ง**ไม่ใช่นักศึกษา**

เดิมที ในการส่ง Metadata ไปยัง n8n Webhook หากผู้ใช้มีบทบาทเป็น `admin` แต่ไม่มีแผนการเรียนในระบบ ตัวแปร `activeCurriculum` ใน Frontend เคยกำหนดค่าเริ่มต้นเป็น `'IT-67'` และ `currentStudentAcademicTerm` กำหนดค่าเริ่มต้นเป็น `'ปี 1 เทอม 1'` ส่งผลให้เมื่อผู้ดูแลระบบถามแชทบอทว่า *"ผมชื่ออะไรตอนนี้ผมเรียนหลักสูตรอะไร"* ปัญญาประดิษฐ์ (LLM) ใน n8n จะเข้าใจผิดว่าผู้ดูแลระบบคือนักศึกษาที่กำลังศึกษาอยู่ในหลักสูตร IT-67 ชั้นปีที่ 1 เทอม 1 หรือถามขอรหัสนักศึกษา (Student ID) จากผู้ดูแลระบบ

นอกจากนี้ เมื่อผู้ใช้ถามคำถามเกี่ยวกับตัวตน (Identity) หรือสถานะการเรียนของตนเอง เช่น *"ผมเรียนผ่านแล้วกี่วิชา กำลังเรียนกี่วิชา และกำลังเรียนปีอะไร"* คำถามเหล่านี้เป็นข้อเท็จจริงระดับ Deterministic จากข้อมูลโปรไฟล์ที่ผ่านการยืนยันตัวตนแล้ว (Authenticated Metadata) ไม่ควรต้องส่งให้ LLM ทำการสังเคราะห์คำตอบหรือดึงข้อมูลเวกเตอร์ผ่าน Pinecone ซึ่งใช้เวลานาน (30–40 วินาที) และเสี่ยงต่อการเกิด Hallucination

## การตัดสินใจ (Decision)

1. **การแยกบทบาทอย่างเด็ดขาดในระดับ Frontend (`Non-Student Role Isolation`):**
   - ตรวจสอบ `isStudent = user?.role === 'student'` ใน `src/components/chat/ChatBot.tsx`
   - สำหรับผู้ใช้ที่ไม่ใช่ `student` (`admin`, `instructor`, `staff`, `guest`):
     - กำหนด `enrolledCurr = ''`, `activeCurriculum = ''`
     - กำหนด `studentId = ''`, `currentStudentYear = null`, `currentStudentSemester = null`, `gpa = 0`, `completedCredits = 0`, `totalCredits = 0`
     - ส่งอาเรย์รายวิชา (`completedCourseCodes`, `passedCourses`, `inProgressCourses`, `failedCourses`, `studyPlan`) เป็นอาเรย์ว่าง `[]`
     - ส่ง Directive `currentStudentStatusRule` กำกับชัดเจนว่าผู้ใช้รายนี้ไม่ใช่ผู้เรียนและไม่มีหลักสูตรผูกมัดในระบบ
   - สำหรับผู้ใช้ที่สมัครสมาชิกใหม่ (Signup) ให้ตั้งค่าเริ่มต้นเป็น `student` โดยยังไม่ผูกสาขาวิชา/หลักสูตร จนกว่าจะเลือกที่หน้าโปรไฟล์หรือหน้าจัดการแผนการเรียน

2. **การคัดกรองตัวตนและสถานะแบบ Deterministic ใน n8n Workflow (`Deterministic Identity & Status Router`):**
   - **Route 0.0 (User Identity & Curriculum):**
     ดักจับคำถามเกี่ยวกับชื่อ ตัวตน หรือหลักสูตรที่กำลังศึกษา (`isUserIdentityOrCurriculumRequest` เช่น *"ผมชื่ออะไรตอนนี้ผมเรียนหลักสูตรอะไร"*, *"ผมเรียนสาขาอะไร"*, *"ฉันเป็นใคร"*)
     - หากเป็น Non-student: ตอบทันที (Bypass 0 ms) ระบุชื่อ บัญชี และบทบาท (ผู้ดูแลระบบ / อาจารย์ผู้สอน / เจ้าหน้าที่) พร้อมแจ้งว่าบัญชีไม่ใช่ผู้เรียน จึงไม่มีข้อมูลหลักสูตรที่กำลังศึกษาในระบบ
     - หากเป็น Student: ตอบชื่อ รหัสนักศึกษา บทบาท และหลักสูตรจริงที่ลงทะเบียนไว้ (หรือแจ้งให้เลือกหลักสูตรหากยังไม่ได้เลือก)
   - **Route 0.1 (Personal Student Status & Year 5+):**
     ดักจับคำถามประวัติและสถานะการเรียน (`isStudentProgressStatusQuestion` เช่น *"ผมเรียนผ่านแล้วกี่วิชา กำลังเรียนกี่วิชา และกำลังเรียนปีอะไร"*)
     - หากเป็น Non-student: ตอบทันทีว่าบัญชีไม่มีประวัติการลงทะเบียนรายวิชาในระบบ
     - หากเป็น Student: คำนวณสรุปจำนวนวิชาที่ผ่าน, วิชาที่กำลังเรียน, ชั้นปีจริง (รองรับปี 5+ พร้อมข้อความแจ้งสถานะนักศึกษาขยายเวลาเรียน), GPAX และความคืบหน้าหน่วยกิตสู่การสำเร็จการศึกษา

3. **การติดตั้ง Role & Identity Truth Lock ใน `AI Agent` System Message:**
   - ติดตั้งกฎห้ามเด็ดขาดไม่ให้ LLM เรียกผู้ดูแลระบบหรือเจ้าหน้าที่ว่า "ผู้เรียน", "นักศึกษา" หรือถามขอ "Student ID"
   - ห้ามนำหลักสูตร IT-67 หรือหลักสูตรใดๆ ไปผูกกับบัญชีที่ไม่ใช่นักศึกษา

## ผลลัพธ์และข้อพิจารณา (Consequences)

- **ความถูกต้อง 100%:** ผู้ดูแลระบบ อาจารย์ และเจ้าหน้าที่ จะได้รับคำตอบที่ตรงตามบทบาทของตนเองเสมอ ไม่มีการแจ้งหลักสูตรเท็จ
- **ความเร็วในการตอบสนอง (Zero Latency):** คำถามเกี่ยวกับตัวตนและสถานะนักศึกษาจะตอบกลับทันที (Bypass n8n AI Agent และ Pinecone Vector Store) ลดเวลาตอบสนองจาก ~35 วินาที เหลือต่ำกว่า 1 วินาที
- **การรองรับนักศึกษาปี 5+ (Extended Duration):** นักศึกษาที่เรียนเกิน 4 ปี (เช่น ปี 5 เทอม 1) จะได้รับการยืนยันสถานะชั้นปีจริงและวิชาที่กำลังเรียนถูกต้อง ไม่ถูกปัดลงมาเป็นปี 4
- **Single Source of Truth:** ข้อมูลสถานะบุคคลยึดจาก Authenticated Metadata ใน Realtime Database เป็นหลัก ไม่เกิดความขัดแย้งกับฐานข้อมูลหลักสูตร
